# Estimation

Use this branch only when the user requests a duration, cost, or schedule. Estimate to avoid surprises, not to manufacture certainty.

### Build the Estimate

1. Ask what the estimate is for and how accurate it needs to be.
2. Define what is included, the required quality, assumptions, and external dependencies.
3. Build a model of the work or system.
4. Break the model into components and assign each parameter a value using experience, comparable work, or measurement.
5. Calculate the result and sanity-check it against the model.
6. Communicate the assumptions and use units that reflect the estimate's precision.

Scale the units to the horizon:

| Expected duration | Quote in |
|---|---|
| 1–15 days | days |
| 3–8 weeks | weeks |
| 8–30 weeks | months |
| More than 30 weeks | revisit the model before committing |

Build the model before presenting an estimate. Gather repository evidence and ask targeted questions for missing constraints. Completion means the recipient knows the estimate's purpose, scope, assumptions, units, and principal uncertainty.

### Iterate the Schedule

A project schedule becomes credible through experience on that project. Repeat:

1. make an initial estimate;
2. check requirements and risks;
3. design, implement, and integrate a bounded increment;
4. validate it with users;
5. update the model and schedule from what happened.

Keep an estimation log with estimate, actual, error, and cause when the project provides that history. Investigate large misses—especially errors greater than 50%—and carry the learning into the next model. Completion means the latest schedule incorporates available project evidence rather than only the initial guess.

## Agent Constraints

Repository evidence rarely captures team availability, review latency, organizational dependencies, or deployment calendars. Ask for missing inputs and label assumptions instead of inventing them. Provide a range or confidence statement only when the model supports it.

Completion means factual repository evidence is separated from user-provided constraints and explicit assumptions.
